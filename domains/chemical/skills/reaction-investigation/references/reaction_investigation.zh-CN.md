# 反应研究闭环

[English](reaction_investigation.md)

本闭环用于回答用户要求的反应/路径问题，不是所有化学计算必须遵守的固定顺序。
从已有证据出发，只补齐缺失操作。Skill 交接改变当前执行的方法；解释结果和继续推进
仍由同一 Agent 负责。

## 保留当前科学决策

在已有 Node 的 proposal/plan/note 中保留当前基元步骤假设、映射物种和电子态、来源材料、
替代方案、观察证据，以及下一项计算的目的和有界设置。每次尝试说明相对上一次改了什么，
什么观察将决定后续行动。使用已有 Job、Artifact 和 Result，不新增运行时 schema，
也不要求每轮填写检查表。重复旧工作前先读取当前评估。

## 操作间交接

| 未解决问题 | 负责操作及可交接产物 | 检查后的决策 |
| --- | --- | --- |
| 用户要求哪些结构？ | [material-preparation](../../material-preparation/SKILL.zh-CN.md)：原始身份、分子图/电子态、显式氢顺序、映射材料及来源几何 | 先修复错误分子图或原子对应；复用可靠优化片段，避免手填坐标 |
| 测试哪个基元步骤？ | reaction-investigation：键变化、构象/位点/电子态、替代假设与可证伪观察 | 端点跨多步时研究中间体；输入错误不否定反应假设 |
| 反应原子如何接近？ | [reactive-geometry](../../reactive-geometry/SKILL.zh-CN.md)：保留来源的姿态、接触/保护键检查及被拒方案 | 检查真实局部几何后选择约束精修或路径搜索；碰撞则修正姿态 |
| 鞍点候选在哪里？ | [candidate-generation](../../candidate-generation/SKILL.zh-CN.md)：QST/TS 优化、扫描或 NEB 输出、选中帧及约束 | 对合理高点做鞍点精修；计算失败先分类，再修改已诊断原因 |
| 是预期鞍点与连接吗？ | [validation](../../validation/SKILL.zh-CN.md)：驻点证据、模式归属、双向 IRC 与端点比较 | 缺证据则安排计算；检查不通过则向构造/搜索返回具体诊断，或修订假设 |
| 支持什么机理？ | reaction-investigation 与 [energetics](../../energetics/SKILL.zh-CN.md)：连通步骤、竞争路径和可比能量 | 识别剩余替代解释与缺失步骤；一个验证过的 TS 不证明整个机理或选择性 |
| 能交付要求的结论吗？ | [report](../../report/SKILL.zh-CN.md)：主张绑定原始材料、条件与局限 | 按约定范围判断完成；未完成计算仍是待办，不能改称成功机理报告 |

使用[候选/验证交接约定](../../candidate-generation/references/reaction_task_interface.zh-CN.md)
明确候选身份及下一项操作。交接实际证据，不是勾选完成的清单；未知、被否定和被支持的
主张必须分开。

## 按操作选择前置条件

一个结构可能适合下一项探索操作，却尚未成为已验证极小点或鞍点。保留生成、受约束、
未收敛几何的真实身份，检查物种、映射、局部几何和电子态。仅通过灾难性重叠检查，
不能证明分子图或片段内部几何正确。

双分子缔合反应开展 TS 探索，并非普遍要求整个反应物复合物先成为频率确认的极小点。
从可靠单体构造保持片段内部结构的映射姿态，再根据证据选择约束精修、扫描、QST、NEB
或直接鞍点优化。QST 需要原子顺序一致的兼容结构；某种 NEB 方法可能需要松弛端点。
核对所选方法的要求，不将一种方法的前提施加于所有替代路线。证据中保留约束；最终
鞍点与连通性结论仍须各自验证。

正/反向 IRC 端点可能需要继续积分或势阱优化；未完成路径不证明连到了错误产物。
完整路径到达另一势阱，或虚频不对应目标步骤，则应帮助修订候选或机理，不能继续从
同一不合适种子索要同样的缺失证据。

## 恢复与停止

每次失败后按[搜索恢复](../../method-selection/references/search_recovery.zh-CN.md)区分输入错误、
执行故障、数值停滞与化学反证。保留失败分支，根据诊断选定变化后的输入或方法，实际
执行下一项已授权操作。重读同一份说明或再发布一次失败总结，不能替代落实修改。

若缺失映射几何可由已给物种构造，就实际构造。重复产生不安全插值应更换构造方法，
不能要求用户提供已完成的端点。脆弱的求解器格式使用已有序列化工具，提交前检查每个结构块。

用构象/姿态数量、优化步数与明确资源额度约束尝试。区分自行选定的单次上限与用户或
安装配置上限：单次尝试耗尽应在授权范围内重新规划，不虚构再次授权要求。总成本
无法合理约束时，与用户明确具体预算。实际额度耗尽、必需资源不可用、只有用户能
解决的歧义或用户要求停止时，说明考虑过的替代路线及具体缺失条件。恢复工作仍遵守
已有 blocked/paused 控制，本 Skill 不覆盖这些状态。

Job 运行期间推进独立问题；只剩等待结果时记录明确 Job 等待并结束本轮，由 Monitor
恢复。恢复后读取待解决决策、检查新收集的证据，从该位置继续。
