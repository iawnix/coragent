## 这类错误表示什么

Gaussian 的 `L101`（Link 101）负责读取计算开始阶段与分子和作业控制有关的基础输入；route 中的关键词会决定 L101 期待哪些后续 section。常见内容包括：

- 标题行；
- 总电荷和自旋多重度；
- 笛卡尔坐标或 Z-matrix；
- 按 route 要求出现的变量、基组、ECP、ModRedundant 等附加 section。

route section（`#` 开头的方法、基组和任务关键词）会在更早的输入阶段被处理；route 拼写错误或选项组合不适用，也可能使后续 L101 进入错误的读取模式。`Error termination via Lnk1e` 前面如果出现 `L101`、`RdGeom`、`charge`、`multiplicity`、`symbol`、`z-matrix` 或 `geometry` 等提示，最常见的原因确实是输入文件的结构或内容错误。`L101` 是读入阶段的名称，不是某一种单独的化学计算错误。

仍需保留一个边界：如果输入要求从 checkpoint 读取几何或电子态，checkpoint 不存在、与输入不匹配或文件损坏，也可能在 L101 附近失败；route 使 Gaussian 进入了不适用的附加输入模式时，也会表现为输入解析错误。因此应先看 L101 之前的第一条具体诊断，不能只根据最后一行 `Lnk1e` 判断原因。

本文只讨论如何按 Gaussian 的公开输入格式创建和检查输入文件，不涉及 Gaussian 源代码、二进制或实现细节。

## 最小的标准输入结构

一个普通单步作业通常按下面的顺序排列。每个用空行分隔的 section 都要保留空行；最后一个数据行后应有一个空行，也就是文件末尾通常保留两个换行符。

```text
%chk=water.chk
%mem=2GB
%nprocshared=4
#p B3LYP/6-31G(d) Opt

Water geometry optimization

0 1
O    0.000000   0.000000   0.000000
H    0.000000   0.757000   0.586000
H    0.000000  -0.757000   0.586000

```

各部分的含义如下：

1. `%` 开头的是可选的作业控制行，例如 checkpoint、内存和并行核数。
2. `#` 开头的是 route section；它结束于空行。
3. route 后的第一段是标题；标题可以是任意说明文字，但必须占据自己的 section。
4. 标题后的第一行是“总电荷 自旋多重度”，例如中性单重态为 `0 1`。
5. 随后是几何。笛卡尔坐标每行通常为“元素符号 x y z”。
6. 几何之后是否还有内容，由 route 中的关键词决定；没有附加内容时以空行结束文件。

如果 route 后缺少标题 section 的空行，或者坐标块末尾没有空行，后面的文字可能被当成坐标或附加数据读取，从而产生 L101 错误。

## 电荷和自旋多重度

电荷和多重度必须写成两个整数，中间用空格分隔：

```text
0 1    # 中性单重态
1 2    # +1 阳离子双重态
-1 1   # -1 阴离子单重态
```

检查以下事项：

- 电荷要带正确的正负号；不要把 `+1`、`singlet` 或文字说明写在这一行。
- 多重度是正整数，满足 `2S+1`；不要写 `0` 或负数。
- 电子总数与所选多重度要相容。偶数电子体系通常不能直接指定奇数电子数的闭壳层单重态，反之亦然；自由基、离子和金属体系应按实际电子态设定。
- ONIOM、QST、多片段或外部电荷输入可能有额外的电荷/多重度行，必须按对应关键词的格式填写，不能把这些行随意合并。

## 几何的两种写法

### 笛卡尔坐标

最稳妥的基本写法是每行一个原子：

```text
0 1
C    0.000000   0.000000   0.000000
O    1.200000   0.000000   0.000000
H   -0.600000   0.900000   0.000000
H   -0.600000  -0.900000   0.000000
```

注意：

- 元素符号必须有效，例如 `C`、`Cl`、`Si`；大小写按 Gaussian 支持的元素写法使用。
- 三个坐标必须是有限的数值；建议使用空格分隔，不要夹入单位字符串、`NaN` 或 `*****`。
- 原子顺序在后续约束、扫描、QST、IRC 和结果分析中有意义；修改顺序时要同步修改所有原子索引。
- `Bq` 是 ghost center，`X` 或 `-` 可用于某些 Z-matrix/dummy-center 场景；只有在明确需要时使用，不能把它们当成普通元素。
- 坐标块结束后必须有空行。坐标后的基组、ECP、ModRedundant 等内容不能紧贴最后一个坐标行。

### Z-matrix

Z-matrix 中，每个新原子只能引用前面已经定义的原子。例如：

```text
0 1
O
H  1  R
H  1  R  2  A

R = 0.96
A = 104.5

```

常见规则是：第二个原子需要一个已定义原子和键长；第三个原子还需要键角；第四个及之后的原子通常还需要二面角。变量名必须在后面的变量 section 中定义，不能拼写不一致或重复定义。

Z-matrix 最容易触发 L101 的问题包括：引用了尚未出现的原子、键长/角度/二面角漏项、同一行混入笛卡尔坐标和 Z-matrix 字段、变量未定义，以及首个三原子几何共线导致二面角无法定义。

如果不需要变量，几何后直接用空行结束即可；如果使用变量，变量定义结束后还要再用空行结束变量 section。

## 依 route 添加附加 section

输入文件不能只看几何，还要检查 route 是否启用了需要继续读入数据的关键词。常见例子如下：

| route/场景 | 几何后可能需要的内容 | 常见 L101 失误 |
|---|---|---|
| `Gen`、`GenECP` | 按元素分组的基组和/或 ECP | 缺少元素终止行 `****`、元素名不匹配、基组段顺序错误 |
| `Opt=ModRedundant` | 约束、冻结或扫描定义 | 原子索引超出范围、字段数量错误、漏掉末尾空行 |
| `QST2`、`QST3` | 两个或三个完整结构 | 结构数量不对、原子顺序/数量不一致、结构之间缺空行 |
| `IRC`、`Scan` 等 | 由具体关键词决定的控制行 | 把控制行当作普通坐标，或将控制行放错 section |
| `Geom=AllCheck`、`Guess=Read` | 从 checkpoint 读取相应数据 | checkpoint 不存在、文件不匹配，或又写入了与读取模式冲突的 section |
| ONIOM、外部点电荷 | 层级、连接原子或电荷数据 | 行格式、原子编号、层级标记或附加数据顺序错误 |

附加 section 的具体格式应以所用 Gaussian 版本的用户手册为准。不要为了“补齐”文件而盲目添加数据；关键词没有要求的 section 反而可能被 L101 误读。

## 多步作业（Link1）

多步输入的每一段都要独立满足自己的格式，并用 `--Link1--` 分隔：

```text
%chk=water.chk
#p B3LYP/6-31G(d) Opt

Optimize

0 1
O  0.0  0.0  0.0
H  0.0  0.8  0.6
H  0.0 -0.8  0.6

--Link1--
%chk=water.chk
#p B3LYP/6-31G(d) Freq Geom=AllCheck

Frequency from checkpoint

```

第二段使用 `Geom=AllCheck` 时，几何、电荷或多重度是否应省略取决于 checkpoint 读取模式；不要把第一段的坐标机械复制到所有段。每一段的 route、checkpoint 和电子态必须互相匹配。

## L101 的优先排查顺序

看到 L101 时，按以下顺序检查比直接修改方法或增加资源更有效：

1. **定位第一条具体消息。** 在输出中查找 L101 之前的第一条 `Error`、`Erroneous`、`Unrecognized`、`End of file` 或几何/电荷提示；最后的 `Lnk1e` 只是终止汇总。
2. **检查 section 边界。** 确认 route、标题、电子态、坐标、附加数据之间的空行都存在，文件没有停在最后一行坐标上。
3. **核对电子态。** 重新计算总电荷、多重度和电子数，确认没有把标题、注释或旧作业的电荷行错当成电子态。
4. **核对坐标。** 检查元素符号、三列数值、原子数量、原子顺序、非有限数和明显的零距离重叠。
5. **核对 Z-matrix 或约束。** 检查所有引用是否指向已经出现的原子，变量是否定义，索引是否在原子数量范围内。
6. **核对 route 触发的附加输入。** 暂时移除不必要的 `Gen`、`ModRedundant`、外部电荷或复杂 checkpoint 选项，先让最小输入通过，再逐项加回。
7. **核对 checkpoint 依赖。** 对 `AllCheck`、`Guess=Read`、`Geom=Checkpoint` 等输入确认文件存在、可读且来自兼容的体系和计算。
8. **对照一个最小可运行案例。** 先用同一方法/基组运行简单分子或单点计算，再逐步加入优化、频率、约束和多步设置。

## 创建文件时的实用检查清单

提交前可以逐项打勾：

- [ ] 文件使用纯文本，避免 Word 富文本、BOM、智能引号和不可见控制字符。
- [ ] `%chk`、`%mem`、`%nprocshared` 等资源行使用目标 Gaussian 版本支持的语法。
- [ ] route 以 `#` 开头，方法/基组和任务关键词拼写正确。
- [ ] route 后有标题 section；标题后有空行。
- [ ] 电荷和多重度是正确的两个整数。
- [ ] 每个原子行的格式一致，坐标为有限数值。
- [ ] Z-matrix 的引用只指向已定义原子，所有变量都已定义。
- [ ] 需要的 `Gen`、ECP、ModRedundant、QST、ONIOM 或外部电荷 section 按正确顺序提供。
- [ ] 每个 Link1 段都能单独解释，段间有 `--Link1--`。
- [ ] 文件最后有空行；不要让文件恰好停在最后一个数据字符。
- [ ] 记录实际使用的输入文件和输出文件，排查时以输出中回显的 route、charge、multiplicity 和坐标为准。

## 在 TSPi 中使用显式 Gaussian 输入

如果通过 TSPi 的显式输入执行器提交 `.gjf`，输入文件仍须遵守 Gaussian 格式；执行器不会替 route 自动补齐标题、电子态、坐标或附加 section。提交前还会检查显式输入的结构，建议将 L101 排查放在提交作业之前。

显式输入使用 `chemical.gaussian-input@1`。`--validation` 只选择后续检查类型，不会替输入文件添加关键词。例如：

```bash
"$CORAGENT_PYTHON" -m research_agent.application.executors \
  --config "$CORAGENT_JOB_CONFIG" \
  --executor chemical.gaussian-input --version 1 \
  --input input=water.gjf --output prepared/water.json -- \
  --method B3LYP --basis '6-31G(d)' --charge 0 --multiplicity 1 \
  --threads 4 --memory-mb 2000 --validation opt
```

准备阶段通过只表示请求和输入格式可接受，不表示 Gaussian 已经正常终止；仍需查看实际输出中的 route 回显、收敛信息和 `Normal termination of Gaussian`。

## 如何最小化一个失败输入

当原始输入很复杂时，复制一份新文件，按下面顺序建立最小案例：

1. 只保留 `%chk`、一个简单 route、标题、正确的电荷/多重度和笛卡尔坐标。
2. 先运行单点；成功后再加入 `Opt`、`Freq` 或其它任务关键词。
3. 一次只加入一个附加 section，例如 `ModRedundant` 或 `Gen`。
4. 每一步都保留新文件名和输出，便于确定是哪一段引入了 L101 错误。

这种方法能把“输入解析失败”和“SCF 不收敛、几何优化失败、资源不足”等后续问题分开。只有当输入成功读完后，才有意义继续诊断 SCF 或优化算法。
