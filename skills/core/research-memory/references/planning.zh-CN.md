# 规划与重访研究问题

复杂研究或新证据改变下一步选择时，使用本文。Node 关系组织问题，plan 保存当前假设与调查方法，note 留存观察和决策；用户任务控制仍由任务工具负责。

## 选择合适的问题粒度

先读取当前任务的研究入口、焦点和相关已有问题，必要时搜索历史研究，复用本次调查所属的问题。只有新的研究目标需要独立持续调查和判断时才创建 Node。一个操作可以单独执行，或产生可复用的中间 Result，都不足以单独成为拆分理由。换命令、参数、初始构型或计算平台本身不产生新问题。

可以检查：换程序、构型或下一项计算后，原 goal 是否仍成立？如果成立，就继续原 Node。“跑频率”“收集输出”属于 plan 或 Job 工作流中的动作。出现独立研究目标后再展开问题图，不按预定计算步骤批量建 Node。

| 研究 | 起始问题 | 同一问题内的工作 |
| --- | --- | --- |
| 分子性质 | 该体系在给定条件下具有什么性质？ | 准备输入、修复收敛、重复计算 |
| 竞争反应路径 | 给定条件下哪条路线更有利，证据是否充分？ | 候选结构、优化、频率/IRC 检查、能量和重试 |
| 周期 DFT | 比较支持怎样的物理差异？ | k 点/截断能收敛与参数表 |
| MD/自由能 | 支持怎样的状态差异或自由能估计？ | 平衡、采样检查、重复轨迹和统计窗口 |
| 模型拟合 | 哪个模型支持预期的预测？ | 数据检查、参数搜索和重复拟合 |
| 理论推导 | 给定假设下能否得出所提结论？ | 引理、近似检查和局部修订；可以没有 Job |

某条路径的机理或方法适用性成为需要独立持续判断的研究目标时，再拆出关联问题。范围明确的比较可以保持一个 Node，包含多个 Job 和 Result；不强制每个 Task 一个 Node，也不强制每条路径一个 Node。

根问题可选，多个任务入口可以表示互相独立的问题。子问题通过 `part_of` 指向总问题，共享问题可以有多个父节点。`requires` 表达真实研究依赖，不代表工具调用先后顺序；确实是替代思路时才用 `alternative_to`。比较结论引用精确的输入 Result。

首个 Node 可以提供初始任务绑定，后续创建不会自动进入任务范围。确实需要新增问题时，声明实际关系，明确选择稳定的任务入口和当前焦点，不把所有新节点都加入两份列表。需要调整时，读取当前任务并完整替换列表：

```json
{
  "action": "set_research",
  "expected_revision": 3,
  "research": {
    "entry_node_ids": ["node_returned_for_the_study"],
    "focus_node_ids": ["node_returned_for_the_study"]
  }
}
```

替换为真实返回的 ID 和 revision。这次操作替换两份导航列表。焦点不是锁、排他所有权或资源授权。一个任务完成时，共享 Node 可以保持 open。只读浏览用 `research_read {ref}` 或 `{ref, field:"relations"}` 及返回的分页，不必更新焦点。

## 根据证据调整计划

恢复时将当前发现、待处理 Job 与用户目标和交付条件对照。下一次尝试有理由提供新信息时才继续该方法。某种方法达到尝试上限后，评估剩余已获授权的路线。Job 运行期间还有独立工作就继续；必须等这些 Job 的结果才能做其它有用工作时，才设置整个任务的等待。

执行错误需要诊断，本身不否定科学想法。检查失败后在原问题上调整方法。排除某个候选是有用的负面证据，不必因此结束整个问题或委托。

重访已关闭的问题时，读取当前字段，用 `research_update` 重开，并在 note 中说明原因和相关证据。只有新的研究目标需要独立持续调查和判断时才新建 Node。保留旧 Job、文件和 Result；适用时复用精确的旧证据，重复外部操作前先核对原回执。

修订已发布结论时，新建 Result 并设置 `supersedes`，适用时选择为当前综合判断。根据复核提醒检查受影响的比较和报告。提醒要求科学复核，不自动否定全部下游结论，也不自动重算。

## 留存进展并完成委托

plan 说明调查方法，已选综合判断说明当前已知和未知。解释一批新结果、改变研究路线、准备等待或交付时，用一次 `research_update` 提供 `note`、实际 `references` 和 `as_assessment:true`，方法变化时再同时修订 `plan`。保留旧判断中仍有效的发现、未解决的身份检查、反证和局限，不只记最后一次计算。普通操作可以留作未选定的过程 note。

Result 固定值得引用的结论，包括阶段性、负面或未定结论，也可以通过 `as_assessment:true` 成为当前判断；不必把同一内容再抄成 note、Result 和任务进展。运行时观察已发布证据和实际 Job 里程碑，Task 的具体 `next_action` 仍由 Agent 选择。进入等待时，在同一次调用中保存所等 Job 与醒来后的行动，避免误留上一项 Job 的下一步。Node plan 保留调查方法，不复制这条续接指令。

改写计划、增加节点、换组合引用相同证据都不构成新的实质进展。无进展计数用于提示重新规划，不是固定停止阈值；继续推进时仍须遵守用户的计算、费用、时间和重试限制。纯推导或规划任务可以把有用推导、完整方案本身保存为 Result/材料。

按用户交付条件给出相关不可变证据和局限。负面或不确定结论可以满足实际委托，但不能擅自降低用户要求的声明强度。Node closed、进程成功都不能单独证明完成。按限制停止无信息增益的重复尝试，分别判断局部方法失败与整个任务阻塞。
